bidflow demo

Runs the project’s real AuctionEngine and budget module in one JVM. Two users search the same market: quality scores personalise the ranking, and clicks spend leased budget until campaigns drop out.

Per request, not per profile

Every search runs a fresh auction. The engine is a pure function — “the user” enters only through the quality score, a predicted click-through rate supplied per user and query.

Time lives in the budget layer

Wallets hold time-limited leases over slices of each campaign’s budget. Clicks decrement locally with no network on the serving path; renewal is seal-then-ask; exhausted campaigns stop showing.

What this demo collapses

One process, one clock: no skew, partitions, or crashes, so overspend is structurally zero here. Those failure modes are covered by the deterministic simulation tests (120 seeds).

Traffic simulation

Clicks are drawn from each ad’s quality score, weighted by position. More relevant campaigns pay less per click and outlast bigger bidders; a campaign leaves the page when its budget is exhausted.

Charged spend is tallied by the demo itself, outside the components under test — the same ground-truth habit the simulation harness uses. Money is integer micros end to end; prices come from price = ceil(rankbelow ÷ own quality), so no advertiser ever pays above its bid.
